# ChronoPilot-Go 0.1.4 本轮改造说明

日期：2026-10-18。

本轮目标是将主题从“只有换色”扩展为可控制按钮和容器轮廓的皮肤系统，同时保留简洁的课程、事项和 Agent 操作流程；启动先读缓存，学校同步在前台异步进行。

## 1. 可以直接使用的结果

| 需求 | 本轮实现 |
| --- | --- |
| 多种额外主题 | 默认、磁带未来、构成主义、瑞士风格、自定义皮肤，共五个选择项 |
| 白天 / 黑夜 | 每套主题都有浅色与深色，模式与风格分别持久化 |
| 按钮独立类 | 51 个显式操作入口绑定语义 CSS 类；循环实例共享对应功能类 |
| 构成主义形态 | 直角、2–2.5 像素粗线框，暖纸 / 炭黑 / 朱红对比；卡片、输入框、筛选按钮同步适配 |
| 瑞士形态 | 2 像素微圆角、1 像素细描边、冷灰层次与克制强调色 |
| 用户自行调试 CSS | 设置中打开编辑器，粘贴 / 修改 / 复制 / 载入默认模板 / 保存并应用 |
| 柔和默认浅色 | 页面 #E9EBEF，卡片 #F3F4F6，次文字 #62666D，减少大面积纯白 |
| 高饱和多色色标 | 九色稳定映射；列表圆点从 12 增至 15，日历点从 4 增至 7，并添加细描边 |
| 缓存优先启动 | 先打开上次账号本地快照；首帧不等待安全存储读取与学校网络 |
| 前台自动检查 | 每分钟检查更新条件，学校请求至少间隔两分钟；手动刷新绕过节流 |

额外主题依旧共用页面结构，保留日历、大课表、倒计时、时间条、分类 / 学科 / 学期筛选。没有加入艺术介绍文案、横幅或新的宣传性页面。

## 2. 用户怎么切换和自定义

### 预设风格

打开设置的“外观主题”，选择风格及浅色 / 深色。无需重启，当前页面与表单内容保留；退出再打开会恢复选择。

### 自定义风格

1. 打开“编辑自定义皮肤 CSS”。
2. 从默认模板开始，或者粘贴其他 Agent 写好的 CSS。
3. App 内自定义版本的根标识必须是 `--style-id: custom;`。
4. 点击“保存并应用”。程序先验证两套颜色和组件属性，再发布主题。
5. 如果 CSS 错误，显示具体原因，当前生效主题保留。
6. “复制 CSS”把编辑框文本写到剪贴板，方便外部保存和继续修改。
7. “载入默认模板”只替换编辑框内容；保存前不会覆盖已生效皮肤。

当前是一个自定义槽位。三套额外内置主题可直接选择；尚未实现任意数量个人皮肤文件的导入列表或文件管理器。可以自行保存多份 CSS 文本，按需粘贴替换。

## 4. 主题系统如何实现

### 加载与校验

`lib/ui/styles.dart`：

- `PilotStyle` 注册主题 ID、名称及资源文件。
- `StyleTokens.fromCss` 读取受限 CSS 结构；颜色只接受六位十六进制，数值采用无单位数字。
- 只允许一个普通根块和独立 `.cp-*` 规则，拒绝嵌套、未知选择器、未知控件属性、非法颜色引用、越界尺寸与超长文件。
- 浅深两套运行时所需颜色均须有效，避免浅色导入成功、切到深色才崩溃。
- `StyleController` 负责选择、明暗和自定义文本保存；解析发生在加载 / 保存时。
- 完整 ThemeData 按风格与明暗缓存；CSS 不在刷新倒计时或逐帧渲染时重复解析。

皮肤不执行脚本、下载图片或注册网络服务；最多 65,536 个字符串单元。校验保证格式与可解析性，不会自动证明整套皮肤的文字对比度达标。

### 每个按钮一个样式类

`lib/ui/controls.dart` 中的 `PilotControl` 保留原生按钮本体及业务回调，额外绑定：

```dart
PilotControl(
  className: 'agent-send',
  kind: 'icon-button',
  child: IconButton.filled(...),
)
```

这对应 `.cp-agent-send`。样式按以下顺序合并：

1. `.cp-button`，所有显式按钮的基础样式。
2. `.cp-icon-button` 等类型类。
3. `.cp-agent-send` 等独立功能类。

可控制圆角、描边宽度、描边色、填充色、前景色。不同操作不再只能共用一种圆角和边框。新增功能无需复制一份按钮实现，绑定唯一类名即可。

AppBar 等位置存在局部组件主题，单纯修改 ThemeData 可能被覆盖；现在使用显式 IconButtonTheme、FilledButtonTheme 等作用于实际按钮。只有悬浮按钮需要局部 ThemeData。图标按钮之间保留间隙，避免相邻边框连成一条线。

按下 / 聚焦覆盖色、禁用状态由组件统一维护；主题不能改变按钮业务含义，也不能用 CSS 缩小点击区域或改变页面位置。框架生成的返回键、日期选择器等使用 Flutter 自身主题，不计入独立操作类清单。

### 容器和轮廓

`PilotVisuals.decoration/shape` 将 `.cp-panel` 和具体容器类合并，统一圆角与描边：

- `.cp-card`：设置分组、方案等 SurfacePanel。
- `.cp-item-card`：事项与日程卡。
- `.cp-composer`：Agent 输入容器。
- `.cp-field`：输入框。
- `.cp-dialog`：确认弹窗及底部面板。
- `.cp-drawer`：历史会话侧栏。
- `.cp-glass`：磁带主题的控制容器。

容器轮廓与裁剪保持一致，不叠加两层不同圆角边框；课程块和日期标记保留专用组件以维持原来的信息结构。部分容器只接入轮廓，填充仍遵循组件语义背景，具体支持范围已写进接口文档。

## 5. 缓存启动与账号恢复

之前的顺序是读取多项安全存储 → 打开数据仓库 → 才显示课程 / 事项。

现在的顺序是：

```text
初始化本地 Hive
  ├─ 并行读取五套小型皮肤资源和上次主题选择
  └─ 读取上次账号指针并打开本地事项快照
                ↓
          直接显示缓存页面
                ↓
     并行读取账号、密码、模型与 API Key
                ↓
       核对账号，连接对应数据仓库
                ↓
       布局完成后异步请求学校数据
                ↓
       新数据写入成功后更新当前界面
```

相关实现：

- `PlannerRepository.openLastAccount()` 只读本地快照，不需要网络或密钥。
- `rememberAccount()` 保存最近使用的数据作用域指针，不存密码或 API Key。
- `PlannerApp` 在缓存已挂载后恢复凭据和同步服务。
- 首帧不等学校数据；请求慢、断网时继续显示缓存。
- 新安装没有学校缓存时，先显示本地空状态；首次连接学校后才有学校数据。
- 首次升级到本轮版本时，旧版本尚无最近账号指针，需要恢复账号后记录；之后即可按该指针读取缓存。
- 缓存损坏时不静默用空数据覆盖，保留错误处理路径。

“前一秒没有刷新结果就用缓存”的处理方式是从一开始就显示已有缓存，不先用一秒等待网络。未在真实手机测冷启动耗时，因此不承诺所有设备从点图标到首帧都小于一秒；Android 进程启动、磁盘性能与首次安装仍会影响耗时。

## 6. 更新机制与“实时”的范围

### 本地修改

添加、编辑、完成勾选和确认 Agent 方案继续通过仓库串行事务保存。保存成功发布监听事件，当前列表、计数和时间安排同步更新；不需要重新启动或手动刷新。

### 学校数据

- 开屏缓存挂载后检查刷新。
- 返回前台时检查刷新。
- 持续前台使用时每分钟检查条件，学校请求间隔至少两分钟。
- 主动点击刷新立即请求，绕过两分钟节流。
- 同一时刻只保留一个学校同步请求，重复点击或不同入口不会启动一批并发同步。
- 请求期间列表仍可操作；顶部用静态沙漏状态表示更新中，不用转圈遮挡页面。
- 同步失败保留已有课程 / 作业 / 考试，设置中仍能查看同步状态。
- 退到后台停止本轮定时检查，恢复前台后重新启动；不引入通知或常驻后台服务。

这里的学校“实时”是前台轮询和主动刷新，不是学校服务端推送。数据通常在下一次检查与请求完成后更新；学校系统自身延迟、登录失败或断网仍会影响新鲜度。

### 时间显示

倒计时由各自的小组件按秒更新；日历日期、事项边界和时间条按分钟重新检查。避免为了秒级数字让整个 App 每秒重新构建。退到后台时停止对应时钟。

## 7. 流畅性与动画处理

- 根 MaterialApp 的主题动画时长为零。
- 自有页面采用 PilotPageRoute，进入与返回过场时长均为零。
- 普通确认弹窗采用无动画样式。
- 历史会话侧栏改为零过场的侧边对话层；支持边缘右滑打开、点击关闭、系统返回、列表滚动、选择会话和新建会话。
- 根 MediaQuery 标记禁用动画，减少框架组件动效。
- 移除磁带控制区 BackdropFilter 实时模糊，保留静态纸面风格。
- 主题资源并行加载，主题构建结果复用。
- 学校请求在首帧后异步进行，不作为启动页面的前置条件。
- 继续使用懒加载列表、有限大小的 CSS 与轻量 SVG 图标，不加入大型图片或新的 WebView 运行时。

上述是代码和组件层面的处理。系统键盘、Android 启动效果等由系统控制，真实设备的帧率、长列表极限和系统级冷启动仍需实机测量。

## 8. 色标与可读性

九色色标为鲜红、金黄、亮绿、青、蓝、紫、玫红、翠绿、橙色。使用学科名称的稳定散列映射，不使用不稳定的运行时 hashCode。

- 同一学科在课表、日历、作业和日程列表中保持同色。
- 无学科的事项以类别映射。
- 列表圆点增大并添加细轮廓。
- 月历圆点增大并添加细轮廓，浅色背景上的黄色也有清晰边缘。
- 课程色标独立于主题色，切主题不会让所有课程变成同一种颜色。
- 九色是有限调色盘，多于九个学科或发生散列碰撞时会重色，不能仅凭色标区分所有课程；标题仍是主要识别信息。

日期选中圆底另按视觉中心向下偏移 2 个逻辑像素，保持日期文字和下方色点原位；今日背景同样处理，避免两种圆底对齐方式不同。

### Android 构建补充

本轮本机 Gradle 默认直连仓库等待较久，纯离线模式又缺少部分工件。为完成构建，使用现有代理下载缺失依赖，并通过 `tools/offline-build.init.gradle` 将插件构建脚本的 AGP 对齐到项目注册的 8.13.2；没有修改第三方 pub-cache 源码。

该初始化脚本只在显式 `-I` 参数下启用，不改变运行时业务。后续更新 Android Gradle 插件版本时，要同步检查脚本版本；离线构建仍要求依赖已缓存。标准在线 Flutter 构建命令继续保留在 README。
